Why it exists

Running a model is easy. Defending the result is not.

When someone asks where a number came from, the usual answer is a notebook and a hope that nothing changed since. These are the guarantees that replace it.

Nothing runs unreviewed

You see the exact file, its checksum, and how it fits the model’s contract — then confirm it explicitly. Nothing executes before you do.

Runs are immutable

Each completed run is written once, with checksums over its own predictions. It cannot be quietly edited into agreement with a later story.

Scores are model output

Component scores are labelled as model behaviour, never as biological causation or clinical evidence. The application does not overclaim on the model’s behalf.

Metrics require permission

Accuracy is never inferred from a column that looks like labels. You choose the column, map the classes, review the coverage, and authorize it.

Nothing is invented

Where a value cannot be trusted — a source file that changed, a denominator of zero — the application says so and withholds it rather than showing something plausible.

What it does

From opening a file to defending a single record.

Review before you run

Exact source identity — filename, dimensions, checksum, delimiter, encoding — beside a faithful read-only view of the rows, and an audit of how they will be aligned to the model.

Profile the dataset

Dimensions, missingness, and categorical group breakdowns, with filters that drill straight through to the exact source rows behind any group.

Investigate the cohort

The score distribution and fixed threshold, with purposeful sets for records near the threshold and records where the ensemble’s own components disagree.

Inspect one record

Select any prediction and its complete original row opens beside it — recovered only while the source file still matches its checksum.

Evaluate against truth

F1, precision, recall, MCC and the confusion counts, with the evaluated denominator and every excluded row disclosed. Error cohorts carry into the records table.

Export the evidence

Every original column beside the predictions, in source-row order regardless of how you were sorting, with a sidecar recording exactly what produced the file.

Model packages

The application ships without a model.

A model package is supplied separately and installed once, from Settings. That separation is deliberate: loading a package deserializes model artifacts, and deserialization executes code.

So a package runs only when its exact manifest checksum is either recognised by the release or explicitly confirmed by you. Loose model files and unpackaged folders are never accepted.

Everything that does not need the model works immediately — source review, dataset profiling, and any runs already in the local archive.

Install

One file. No installer.

$ chmod +x Resolved_Layers-0.1.0-x86_64.AppImage $ ./Resolved_Layers-0.1.0-x86_64.AppImage

The file bundles its own runtime, interface framework and model libraries. Nothing else is required, and deleting it removes the application completely.

Requires Linux x86-64 with glibc 2.35 or newer — Ubuntu 22.04+, Fedora 36+. Download the AppImage, not the source archives attached automatically to the release.

Who we are

Computational Health Lab turns complex health data into transparent, testable computational evidence.

We build tools where the reasoning is inspectable rather than asserted, because a result nobody can check is not a result. Resolved Layers is our desktop product for exactly that.

Its current workflow predicts missense-variant pathogenicity. The model behind it was developed for the TEKNOFEST 2026 AI in Health competition, where we compete as a finalist — one deployment context for this work, not its purpose.
